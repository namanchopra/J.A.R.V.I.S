## Manual scenarios

### Scenario 1 — Manual start/stop (happy path)
- [ ] Open Jarvis (main HUD visible).
- [ ] Open the overlay (`⌥ + Space` default).
- [ ] Locate the 5th icon in the control row — red `●` between interrupt (`■`) and back-to-main (`⤢`).
- [ ] Click the `●` icon. Permission probe runs on FIRST-EVER click (one-time macOS prompt may appear).
  - On grant: orb gains a red ring; state label reads `RECORDING MEETING`; hint line ends with `· REC`.
  - On denial: in-overlay warning appears with "tap to open System Settings" — STOP scenario 1, go to scenario 4 to re-grant, then restart scenario 1.
- [ ] Speak a few sentences naturally (~10-15s of speech).
- [ ] Click the `●` icon again (now `■` STOP state).
- [ ] Within 2-3 seconds, hear Jarvis speak a 2-sentence recap.
- [ ] Toast appears: `✓ Notes saved: 2026-XX-XX-HH-MM-<slug>.md`
- [ ] Verify file landed: `ls -la ~/.jarvis/meetings/ | tail -3`
- [ ] Open the file. Verify it contains: title header, summary section, key points, action items (if mentioned), raw transcript with mic-source tags.

**Expected file structure:**
```
# <Meeting Title>

_Started: 2026-XX-XX HH:MM (TZ) — duration: ~Xm_

## Summary
<2-3 bullet summary>

## Key Points
- <bullet>

## Action Items
- <bullet, or "(none)">

## Recap
<2-sentence prose summary — this is what Jarvis spoke>

## Raw Transcript
[mic] HH:MM:SS — <utterance>
```

### Scenario 2 — Calendar auto-suggest + auto-stop
- [ ] Create a Google Calendar event titled `test sync` starting 2-3 minutes from now, duration 1-2 minutes. (Title must contain a word from `cfg.meetingKeywords`: `call`, `sync`, `1:1`, `meeting`, `standup`, `review`, `interview`.)
- [ ] Within 60-120 seconds, the main HUD shows a top-center banner: `⌖ MEETING IN ~XM` + the event title + `[START]` + `[DISMISS]` buttons.
- [ ] Click `[START]`. Banner disappears. Meeting begins (red ring on orb, RECORDING MEETING label).
- [ ] Speak a few sentences. Wait for the event's scheduled end time.
- [ ] At the end time (or within 30s of it), the meeting auto-stops. Notes file lands. Recap is spoken.
- [ ] Verify the notes file's `_Started:` timestamp + duration match the calendar event window.

**Auto-stop gate:** Auto-stop ONLY fires for banner-started meetings. If you start a meeting manually via the overlay `●` icon, it never auto-stops at a calendar-end time — that's correct behaviour. To verify the gate: start manually, wait through the same end-time window, confirm meeting is STILL recording.

### Scenario 3 — System audio capture
- [ ] Open YouTube (or any browser tab with audio) in a separate window.
- [ ] Start a meeting via overlay `●` icon (or HUD chip).
- [ ] Play 10-15 seconds of clearly-spoken audio in YouTube (a news clip, a podcast — not music).
- [ ] Stop the meeting.
- [ ] Open the markdown file. The Raw Transcript section should contain entries tagged `[system]` whose text approximates the YouTube audio.
- [ ] (Both `[mic]` and `[system]` tagged entries can appear if you also spoke during capture — both should be present and distinguishable.)

### Scenario 4 — Permission denial path (failure case)
- [ ] System Settings → Privacy & Security → Screen Recording → toggle Jarvis OFF. Confirm.
- [ ] Restart Jarvis (or wait for the live permission revocation to propagate).
- [ ] In the overlay: click the `●` icon. Observe in-overlay warning row: `⚠ Screen Recording permission required for meeting mode · tap to open System Settings`.
- [ ] Click the warning row. System Settings opens to the Screen Recording pane.
- [ ] Re-toggle Jarvis ON in Screen Recording. Restart Jarvis if macOS prompts.
- [ ] Click the `●` icon again. Recording starts cleanly — no leftover error state.
- [ ] Verify in Settings → Meeting tab: the warning row that mirrors the overlay's also surfaced (event-driven via `meeting:permission_error`). Re-granting clears it on the next start.

### Scenario 5 — Empty meeting (failure case)
- [ ] Start a meeting via the overlay `●` icon.
- [ ] Immediately click it again to stop (within 1 second).
- [ ] A markdown file should still be written, with a "(no audio captured)" stub for the summary.
- [ ] Recap line is NOT spoken (no recap for empty buffers — verified by `test_empty_buffer_stop_skips_llm_call`).
- [ ] Toast still appears: `✓ Notes saved: ...`
- [ ] Open the file; verify the stub structure:
  ```
  ## Summary
  _(no audio captured)_
  ## Raw Transcript
  _(no transcript entries)_
  ```
